# Metroman 深圳数据包字段说明

`20260628` 是一套以全局数字索引关联的 CSV 数据。文本名称和坐标集中保存在 `uno.csv`，其他文件主要引用其中的线路、方向和站点索引。

## 核心文件

### `uno.csv`

分隔符为 `<,>`，是 ID 字典和多语言元数据。

- `ML`：线路；包含英文、简体中文、繁体中文、日文、显示编号和颜色。
- `MW`：行车方向；例如 `SZMW01A` 表示1号线机场东方向。
- `MS`：站点；包含英文、简体中文、繁体中文、日文、拼音、缩写、纬度、经度和地图坐标。
- `WL`：步行连接。

### `line.csv`

格式为：`线路ID, 站点索引0, 站点索引1, ...`。

站点索引是从0开始的全局索引：`0` 对应 `SZMS001`。列表顺序就是线路上的站序。`SZML02` 在该数据包中表示2号线与8号线的贯通线路。

### `way.csv`

格式为：`方向ID, line.csv中的线路行索引, 交通方式, 有序站点索引...`。

同一条线路通常有 A、B 两个相反方向。地铁方向ID对应同名的 `SZMW*.csv` 时刻文件。

### `link.csv`

每行描述一个有方向的相邻站连接，共29列：

1. 方向在 `way.csv` 中的行索引。
2. 起点站全局索引。
3. 终点站全局索引。
4. 区间距离，单位米。
5. 连接类型。
6–9. 线路图形路径索引范围。
10–19. 十种日历类型对应的时刻表起始行索引。
20–29. 十种日历类型对应的时刻表结束行索引，包含结束行。

相同起止索引表示不同星期共用同一组时刻数据，`-1` 表示该日历类型不适用。

### `SZMW*.csv`

每行两个整数：`相邻区间起点计划分钟, 相邻区间终点计划分钟`，分钟数从当天00:00开始，跨午夜列车可以超过1440。

`link.csv` 后20列用于定位某个相邻区间在该方向时刻文件中的有效行范围。两列之差就是该趟车在相邻站时刻点之间的计划耗时。该数据为分钟精度，没有独立的停站秒数字段；连续区间还可能包含短线车和不同交路，因此不能可靠地把行间差值解释成停站时间。

### `schedule.csv`、`wayschedule.csv`

- `schedule.csv`：日历类型定义，覆盖星期、节假日和调休工作日。
- `wayschedule.csv`：每个行车方向使用的时刻表总长度及适用日历类型。

### `station.csv`

格式为：`站点ID, 换乘站标记, 预留属性标记`。本数据包中第一项为 `1` 的站点是换乘站，第二项全部为 `0`。站名、坐标和多语言文本仍以 `uno.csv` 为准。

### `transferfrom.csv`、`transferto.csv`

两份文件保存同一批有向连接关系，只是分别按进入连接和离开连接建立索引。每行前两项是 `link.csv` 中的进入连接行索引和离开连接行索引，后三项是连接类型及换乘耗时/惩罚参数；常见的 `2,180,3` 表示一次约3分钟的换乘。时长图会保留“站点＋线路”的状态，并在切换线路时加入这里定义的有向换乘时间。

### `path_rail.csv`、`path_latlng.csv`

- `path_rail.csv`：线路相邻站与轨迹点索引范围的对应关系。
- `path_latlng.csv`：轨迹点纬度、经度。

### `fare.csv`、`fare1.csv`、`fare2.csv`

- `fare.csv`：票价方案、适用方向、票价矩阵文件和站点顺序。
- `fare1.csv`：深圳地铁票价矩阵。
- `fare2.csv`：坪山云巴票价矩阵。

## 本项目的提取方式

`tools/extract-line-metrics.mjs` 会：

1. 通过 `uno.csv` 解析线路、方向和站名。
   Metroman 使用“湖贝(2号线)”一类后缀区分不同线路的同名换乘记录，输出时会移除该后缀并合并为同一物理站点。
2. 通过 `line.csv` 与 `way.csv` 建立线路站序和双向关系。
3. 通过 `link.csv` 读取准确区间距离及有效时刻行范围。
4. 从 `SZMW*.csv` 计算双向区间计划耗时中位数。
5. 从 `transferfrom.csv` 提取站点在线路之间的有向换乘时间。
6. 输出 `public/data/metro-line-metrics.json`。
